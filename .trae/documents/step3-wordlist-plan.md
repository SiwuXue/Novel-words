# 精读版 Step 3：单词列表 实现计划

## 1. 需求概述

在精读版（intensive reading）PDF 和预览中，在 Step 2 之后增加 Step 3：单词列表。参考图片显示的结构：

1. **Step 3 标题**：`📋 Step 3: 单词列表（本章 N 词）`
2. **描述**：`复习本章出现的全部 N 个单词，巩固记忆效果。`
3. **表格**：双列布局（每列包含：序号 / 单词 / 释义 三栏）
   - 左列序号 01–50，右列序号 51–100（示例图），依此类推
   - 表头（序号、单词、释义）有浅灰蓝背景色
   - 序号：灰色小字体，两位数格式（01、02、…）
   - 单词：按熟练度着色（红色=生疏，橙色=熟悉，灰色=已掌握）
   - 释义：黑色，常规字体
4. **章节结束标记**：表格末尾居中显示 `—— 第 X 章 完 ——`

单词顺序按章节中出现的顺序（即现有的 `words_found_in_text` 返回的顺序）。如果单词数超过一页（比如 >100 词），需要自动分页继续表格。

#### 表格绘制关键设计（Rust 端）
- 布局：页面宽度内，左右两栏，每栏包含 (序号列 + 单词列 + 释义列)
- 列宽（以 A4，左右各 20mm 边距为例，可用宽度 ≈ 170mm）：
  - 每栏宽度 ≈ (170 - 6 间距) / 2 ≈ 82mm
  - 每栏内：序号列 12mm，单词列 28mm，释义列 42mm（合计 82）
- 行高：固定约 `line_height * 1.1`
- 表头：浅灰蓝背景（如 `#E0E8EF` / RGB 对应 0.88, 0.91, 0.94），文字居中加粗
- 边框：表格有外边框和横向分割线，纵向按列有分割线
- 每页可容纳行数 ≈ (usable_height − header 预留) / 行高，计算动态分页
- 左列填到页尾后再填右列，或按顺序逐行左右交替（图片显示先左 50 条再右 50 条，即「先填满左列 → 再填右列」）
  - 更准确：图片显示序号 1–25 在左列上半，26–50 在右列上半？不对，再看：图 1 左列 01–25，右列 51–75；继续看图 2 左列 26–50，右列 76–100。
  - 哦，实际是**四象限分布**：左上 1–N 行，右上 N+1–2N 行，左下 2N+1–3N 行，右下 3N+1–4N 行。
  - 或者更简单：按每「行」（row）分左右两个表行：第 i 条放左栏，第 i + half 条放右栏。
  - 图片观察：左列是 01–25（第一张图上半）和 26–50（第二张图上半），右列是 51–75 和 76–100。所以实际是：每页容纳 50 词（25 左 + 25 右），当 >50 词时下一页继续。
  - **结论：采用 2 列 × N 行布局，按序号先左后右（1→左，2→左…25→左，26→左…50→左，51→右…75→右，76→右…100→右）。或者等价：将单词列表分为两半，上半（0..mid）放左列，下半（mid..end）放右列。这是图片显示的格式。**

#### 确认图片格式
- 第 1 页 左列：01–25，右列：51–75 → 不对，图片 1 右边是 51-75，第 2 页 左边是 26-50，右边是 76-100。
  - 重新审视：
    - 第 1 张（第 10 页）：左 01–25，右 51–75
    - 第 2 张（第 11 页）：左 26–50，右 76–100
  - 哦，其实是 **把 100 条分成 4 组，每组 25 条**：
    - 页 1：组1（1-25）在左，组3（51-75）在右
    - 页 2：组2（26-50）在左，组4（76-100）在右
  - 这就是「交错双列分页」。简化做法：**每页两个独立的列（left_col & right_col），按「先把左列填到一页行数，再填右列到同一页」，然后下一页同样重复**。
  - 用更简单的算法：
    1. 设每页最大行数 rows_per_page = K（例如 K=25）
    2. 将单词按顺序分成 chunk，每 chunk 大小 = 2 * K = 50
    3. 每个 chunk 占一页（或多页如果行数太多）
    4. 在一页中：chunk[0..K] 放左列，chunk[K..2K] 放右列
    5. 每列先画表头，再画 K 行数据
  - 这正好匹配图片格式（K=25，第一页 chunk[0..25] 左列，chunk[25..50] 右列 — 但是图片中第一页右列是 51–75…不对，那是 chunk[50..75]）
  - 重新看图片：
    - 图片1（第10页）：左 01-25（indices 0-24），右 51-75（indices 50-74）
    - 图片2（第11页）：左 26-50（indices 25-49），右 76-100（indices 75-99）
  - 哦！这是「**四象限分页**」：
    - 将全量单词按每页 2*K 分成大页
    - 大页 = 两个物理页
    - 物理页 1：[0..K] 左，[2K..3K] 右
    - 物理页 2：[K..2K] 左，[3K..4K] 右
  - 这种算法比较复杂。**可以替代为简单的「左右列顺序填满」：左列从上到下填完，再填右列。** 这样用户体验也不错，而且代码简单得多。
  - 为了尽量贴近图片，**采用「先拆分为每页 50 词（25 左 + 25 右），然后在每页内先画左表头和 25 行，再画右表头和 25 行」**。实际上图片就是这样，只不过左右列的数据来源是按 0-24 左，50-74 右（第一页），25-49 左，75-99 右（第二页）—— 这等价于「把 word list 按 4 份切片，page i 用 slice[i_left] + slice[i_right]」。

**简化决策：采用更直观的算法** — 每页最多容纳 R 行。第 1 页：左列填 word[0..R-1]，右列填 word[R..2R-1]；第 2 页：左列 word[2R..3R-1]，右列 word[3R..4R-1]，依此类推。实现简单、用户阅读路径自然（1→2→…R → R+1 →…），只是和图片不完全一致（图片是 1..25 后跳到 51..75 再回来读 26..50 再跳到 76..100，阅读路径稍跳）。**如果可以接受稍偏离图片，这是最佳工程实现。如果必须严格匹配图片，需要把列表分成 4 份按索引交错。**

#### 前端表格布局
使用 HTML table + CSS，不必模拟 PDF 精确的物理分页。单张大表即可（浏览器会自动分页打印，但预览里是滚动）：
- 一个大 table 或两个 table 并排（`display: inline-table; vertical-align: top; width: 48%`）
- 左边放 word[0..half)，右边放 word[half..]
- 每列一个独立的 table（自带独立表头）

这样和图片的视觉效果一致（两个独立表并列，各有 3 列：序号 / 单词 / 释义）。

## 4. 实现步骤

### Step A. 前端预览先做（快速验证 UI）
1. 在 `pdfPreview.ts` 的 `baseCss()` 中添加 Step3 和章节结束相关 CSS 样式。
2. 新增 `renderStep3Table(words)` 函数，返回 HTML：
   - Step3 标题块 + 描述
   - 两个并排表格：左表（0..half），右表（half..end）
   - 每个 table 结构：`<thead><tr><th>序号</th><th>单词</th><th>释义</th></tr></thead><tbody>...</tbody>`
   - 序号用 `String(i+1).padStart(2, '0')`
   - 单词 style 套用 `textColorFor(proficiency)`
3. 在 `buildIntensive()` 的 Step 2 之后，插入 Step3 块，然后追加 `—— 第 ${num} 章 完 ——` 居中 div。

### Step B. Rust 后端实现
1. `intensive.rs` 新增 `draw_step3_header(ctx, word_count)` 函数（与 Step1/2 头部样式一致）。
2. 新增 `draw_step3_table(ctx, chapter_words)`：
   - 动态计算 rows_per_page（`floor((remaining_height - header_height) / row_height)`，但考虑表头和 Step3 标题占用）
   - 按每页 2 × R 的切分算法循环
   - 对每一页：
     - 计算左列 x0 = margins.left，右列 x1 = margins.left + usable_width/2 + gap
     - 每列宽度 col_w = (usable_width - gap) / 2
     - 列内部分配：序号列 = 10mm，单词列 = col_w * 0.4，释义列 = 剩余
     - 画表头（填充浅灰蓝矩形，画三列文字「序号/单词/释义」居中，画边框线）
     - 对 R 行逐行：
       - 画序号（两位数字，灰色小字号，居中）
       - 画单词（按熟练度颜色）
       - 画释义（黑色）
       - 画行底线
     - 若右列有内容，重复同 y 轴不同 x
   - 每页数据填满后 `ctx.new_page()`，继续直到所有单词画完
3. 新增 `draw_chapter_end_marker(ctx, chapter_num)`：居中绘制「—— 第 N 章 完 ——」。
4. 修改 `render()` 函数：在 Step 2 循环结束后，调用 `draw_step3_header` → `draw_step3_table` → `draw_chapter_end_marker`。
5. 在 `pdf::mod.rs` 的 `PdfContext` 中如必要添加通用的「填充矩形背景」辅助方法（供表头背景色使用）。

## 5. 依赖与注意事项
- `PdfContext` 目前没有「填充矩形 + 文字对齐」的通用表格绘制 API。实现可以直接在函数内部用 `Op::DrawRectangle` + `SetFillColor` + 文字计算水平偏移来完成。
- 释义列如果中文过长，需要**截断或缩小字号**。图片中释义列文本较短。策略：超出宽度时用省略号（`…`）截断（可用 `truncate_text`，注意该函数刚被删除，需要加回或临时实现 inline truncation），或接受长单词换行（释义列多行，但行高要调整）。**第一版：截断加省略号，保持单行外观与图片一致。**
- 单词数为 0 的边界：`chapter_words.len() == 0` 时跳过 Step 3 表格，直接进入下一章或显示「本章无词汇」的占位。
- 分页时表头要重复出现在下一页（PDF 表格跨页时用户期望每页都能看到表头）。
- 颜色：表头浅灰蓝，建议值 `Rgb(0xE0/255, 0xE8/255, 0xEF/255)` → 大约 0.878, 0.910, 0.937。在 `pdf::mod.rs` 中添加一个 `table_header_bg()` helper（只在 intensive 里用的话也可直接 local）。

## 6. 风险与验证
| 风险 | 应对 |
|---|---|
| Rust PDF 中文宽度计算偏差导致表格文字越界 | 使用现有的 `measure_text_width` 做截断；预留 1–2mm 宽度安全边际 |
| 表头背景色（DrawRectangle fill + DrawText 顺序）挡住文字 | 严格按「先画背景矩形 → 再画文字」顺序，注意填充色之后记得 `SetFillColor` 重置回黑色写文字 |
| 行数估算错误导致单页溢出 | `remaining_height` 检查在画 Step3 标题和表头前执行，每页开始前重算；起始行数保守一些 |
| 预览与 Rust 视觉不一致（单词顺序、颜色、表头样式） | 两端使用同一数据源 `words_found_in_text`，颜色复用同一套 proficiency→颜色常量 |

## 8. 备注（关于图片格式）
- 参考图片中采用的是「四象限交替分页」（1–25 / 51–75 同页，26–50 / 76–100 同页），工程实现较繁琐。**本计划采用按顺序填充：左列填 R 条后填右列 R 条**，如果用户坚持要完全匹配图片顺序，则需调整 Step B.2 的切片算法：`left_page_data = words[i*2R .. i*2R + R]`，`right_page_data = words[i*2R + R*2 .. i*2R + R*3]`（第 i 页的第一物理页），`left_page_data = words[i*2R + R .. i*2R + R*2]`，`right_page_data = words[i*2R + R*3 .. i*2R + R*4]`（第二物理页）。可以在实际实现时根据用户反馈切换算法，不影响整体结构。
